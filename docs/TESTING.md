# Testing

Every module was built test-first: small unit tests for each piece, then integration
tests with **real models on real audio**, then a browser end-to-end test.

## Running the tests

```bash
uv venv && source .venv/bin/activate
uv pip install -e ".[dev,onnx]"        # on a Mac: ".[dev,mac]"

pytest -m "not integration"            # ~80 fast unit tests, about 2 s, no models needed
pytest -m integration                  # real Whisper (+ Ollama if running) on the test audio
pytest tests/e2e -m integration        # browser test (needs: uv pip install playwright)
```

Environment variables for integration tests:

| Variable | Default | Meaning |
|---|---|---|
| `VOICENOTES_TEST_BACKEND` | `sherpa-onnx` | `mlx` on a Mac, or `faster-whisper` |
| `VOICENOTES_TEST_MODEL` | `small` | Whisper size used in tests |
| `VOICENOTES_TEST_LLM` | `gemma3:1b` | Ollama model for the LLM tests (skipped if Ollama is not running) |
| `VOICENOTES_TEST_TRANSLATOR` | `google` | Translator used by the browser test |

## Test audio

`tests/fixtures/audio/` contains three clips generated by `scripts/make_test_audio.py`
(Google's free text-to-speech). `manifest.json` holds the exact text spoken.

| Clip | Language | Content |
|---|---|---|
| `english_todo.wav` | English | Week plan with 3 tasks (bank/loan, presentation, groceries) |
| `urdu_todo.wav` | Urdu | Thinking about a business plus 3 tasks (bank, call sister, buy vegetables) |
| `urdu_mixed.wav` | Urdu with English loan-words | "I want to build an application that turns my voice into text…" |

Add your own recordings to `tests/fixtures/audio/` to check accuracy on your voice.

## What is tested

| Area | Unit tests | Integration (real) |
|---|---|---|
| Audio decoding and silence chunking | ✅ synthetic tones/silence, corrupt files | ✅ fixtures through ffmpeg |
| Whisper backends | ✅ fake backend: argument checks, Hindi→Urdu, repetition-loop removal | ✅ Urdu and English transcription, language detection, last word not cut off |
| Ollama client | ✅ mocked HTTP: errors, missing model, `<think>` stripping | ✅ real model (CI macOS) |
| Translators | ✅ chunking and context, retry/backoff on rate limits | ✅ Google live; LLM in CI |
| Refiner | ✅ summary guard, JSON parsing, multi-chunk merge cannot drop tasks | ✅ real model cleans text and extracts the "bank" task |
| Notes | ✅ section order, YAML escaping, RTL block, file-name safety, collisions | — |
| Pipeline | ✅ Urdu/English paths, forced language, Whisper/Google/none modes, Ollama-down fallback, silent audio | ✅ CLI on fixtures |
| Server/API | ✅ upload → job → note, settings validation/persistence, retry, errors | ✅ browser |
| UI | — | ✅ Chromium with a fake microphone plays the Urdu clip; the UI records, uploads and shows the translation |

## Continuous integration

`.github/workflows/ci.yml` runs on every push:

- **Linux:** unit tests, real Whisper (ONNX) integration tests, and the browser E2E test.
- **macOS 14 (Apple Silicon):** installs ffmpeg and Ollama, pulls `gemma3:1b`, runs the
  unit tests, then the MLX-Whisper and real-LLM integration tests, then the full pipeline on
  the Urdu clip (the resulting note is printed in the log). It then builds the
  `.app` and `VoiceNotes-Installer.dmg` (downloadable from the run's *Artifacts*).

## Results from the Apple-Silicon CI run (gemma3:1b, Whisper small)

LLM translation of the Urdu test sentence:
> "Today, I'm thinking about my new business. I had to go to the bank this morning to submit a loan application. Besides that, I had to call my brother. And in the evening, I need to buy vegetables from the market."

It recovered "loan application" (Whisper translation: "duty of Friday"; Google: "wallet").
The tiny 1B model did get "sister" wrong and some tenses off. This is why the default for daily use is the 12B model.

**Full pipeline with the tiny CI models (Whisper small + gemma3:1b):** every stage ran and
a complete note was written (title, to-do checkboxes, key points, clean text, translation, Urdu).
But quality was poor: Whisper-small misheard two words, and the 1B model then invented
"my new assistant". The CI models prove the *plumbing*. Translation *quality* depends on the
real defaults (Whisper large-v3-turbo + gemma3:12b), which still need to be evaluated on your
Mac with your own voice (see ROADMAP step 1).

## Note on the development environment

The cloud machine used to build this could not reach Hugging Face or ollama.com. So:
Whisper was tested there through `sherpa-onnx` (models come from GitHub releases), and
the Mac-specific path (MLX + Ollama) is verified by the macOS CI job.
